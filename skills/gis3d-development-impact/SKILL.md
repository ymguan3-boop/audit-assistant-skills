# GIS 3D 開發影響評估 Agent Skill

## 0. 技能目標

本技能用於建立「開發行為周遭影響 3D GIS 初步評估系統」。

適用對象包括但不限於：

- 新建大樓
- 集合住宅
- 公共建築
- 學校
- 醫療設施
- 橋梁
- 道路
- 停車場
- 公園
- 水利設施
- 其他公共設施

主要輸出：

1. 互動式 GIS 3D 網頁
2. 基地與擬建工程 3D 模型
3. 250m / 500m / 2km / 5km / 10km 分層影響分析
4. 生態、交通、水文防災、都市機能、環境、碳排六大主題分析
5. 資料來源、年份、可信度與缺漏資料清單
6. Excel 分析成果檔
7. 後續應向主管機關或設計單位取得之資料建議

# 1. 強制限制

## 1.1 不得要求申請 API Key

本技能不得要求使用者申請或提供：

- Google Maps API Key
- Google Cloud Billing
- ArcGIS Token
- Mapbox Token
- 任何付費地圖金鑰
- 商業 GIS 授權
- 需人工申請之私人 API Token

允許使用：

- 政府公開下載檔
- 政府免申請 WMS
- 政府免申請 WMTS
- 政府免申請 WFS
- 政府免申請 3D Tiles
- 政府免申請 I3S
- 公開 CSV / JSON / GeoJSON / SHP / KML / GeoTIFF / DEM / DTM
- 有明確開放授權之非政府資料作補充

若某資料來源需要 API Key、登入、Token 或申請：

1. 不得停止專案
2. 標記為 `RESTRICTED`
3. 尋找免申請替代資料
4. 若無替代資料，改以 `NOT_AVAILABLE` 記錄
5. 繼續完成其餘可完成之分析

# 2. Google Maps 使用規則

Google Maps 只能作為：

- 人工搜尋基地
- 人工確認基地位置
- 人工選點取得經緯度
- 外部定位參考
- 使用者確認周遭現況之視覺參考

不得：

- 擷取 Google Maps 圖磚作為 GIS 底圖資料庫
- 從 Google Maps 衛星影像描繪建物
- 從 Google Maps 反向建立道路 GIS
- 從 Google Maps 建立 DEM / DTM
- 從 Google Maps 產生 3D 建物模型
- 對 Google Maps 畫面大量擷取地理資料
- 將 Google Maps 截圖視為正式 GIS 幾何資料

GIS 幾何、地形、地籍、道路、水文、土地利用、建物等，
必須優先使用政府公開資料。

# 3. 基地輸入方式

本技能提供以下兩種正式基地輸入模式，**使用者於前端起始頁擇一進行**，全部操作可於前端直接完成，無需另開多個 Google Maps 視窗。

- **地圖選點模式**：預覽底圖（Cesium 免Key）已備妥，支援地址輸入後聚焦該地址位置，讓使用者以**點擊位置方式**（左鍵點擊 → 確定點位 / 重新選點）直接於預覽底圖選點。
- **地號選點模式**：開啟公開地籍圖資（NLSC 免申請），支援**詳細地號或模糊地號**輸入進行選點，選點後再進行下一步。

使用者必須先於前端選擇其中一種模式，後續流程依所選模式分支；未選擇前不顯示兩模式混合輸入。

---

## Mode 1：地圖選點（預覽底圖直接點擊）

**模式定義**：地圖選點 = 預覽底圖（Cesium）直接互動選點，輔以地址聚焦與 Google Maps 僅作視覺參考（不得作為 GIS 幾何來源）。

### 操作流程（前端直接完成，無需另開多視窗）

1. 使用者於起始頁選擇「**地圖選點模式**」
2. 於地址欄輸入地址（例：`宜蘭縣五結鄉利澤村` / `五結防潮閘門`）→ 按「**地址聚焦**」，系統呼叫後端 `/api/geocode`（Nominatim 免Key）將預覽底圖（Cesium）飛至該地址
3. 在**預覽底圖**上以**滑鼠左鍵點擊**基地中心位置，系統立即顯示待確認點位標記（綠點）
4. 點擊後可選擇「**確定點位**」或「**重新選點**」
5. 按「確定點位」即將該點 WGS84 經緯度寫入為正式基地定位，並自動轉 `EPSG:3826 TWD97 / TM2 zone 121`

接受格式（確定後自動寫入）：

```text
24.750123, 121.760456
```

或：

```text
lat: 24.750123
lon: 121.760456
```

Agent 必須：

1. 解析 WGS84 經緯度
2. 設定為基地參考中心點
3. 轉換至 `EPSG:3826 TWD97 / TM2 zone 121`
4. 以投影座標進行公尺、距離與面積分析
5. 於前端轉回 WGS84 顯示

### 前端直接操作要求

- 預覽底圖必須已備妥並可直接點擊選點，不得要求使用者另開多個 Google Maps 視窗完成選點
- 預覽底圖（Cesium）需疊加 **NLSC WMS/WMTS 底圖**（臺灣通用電子地圖）作為基礎模型底圖，基礎模型互動網頁必須可見 NLSC 圖層
- Google Maps 僅作為地址搜尋與視覺參考補充，GIS 幾何仍以政府公開資料與本次點擊點位為準
- 未按「確定點位」前，不得視為完成選點
- **確定點位後，前端自動回傳至 Agent 對話框**：前端顯示「定位完成，請回到對話框」完成頁，座標自動 POST 至 `/api/site/set`，其餘 Phase 2–12 轉由 Agent 對話框作業，使用者無需再於前端逐項操作

### Google Maps 截圖

若使用者另提供 Google Maps 截圖：

- 僅作基地與現況視覺參考
- 不作 GIS 精密量測
- 不直接由截圖產生地籍界線
- 不直接由截圖產生正式建物 footprint

如已於預覽底圖確定點位，Agent 可直接開始分析。

## Mode 2：地號選點（公開地籍圖資，支援模糊）

**模式定義**：地號選點 = 公開地籍圖資（NLSC 等免申請 WMS/WMTS）直接於前端輸入地號並選點，全部於前端完成，支援詳細與模糊輸入。

### 前端直接操作流程

1. 使用者於起始頁選擇「**地號選點模式**」
2. 系統於前端開啟**公開地籍圖資**（NLSC 嵌入 iframe 供對照），並提供地號輸入欄
3. 輸入**詳細地號**（`宜蘭縣五結鄉○○段123地號` 含縣市/鄉鎮/段/地號）或**模糊地號**（`五結段 123`、`大吉段456`）
4. 按「**地號查詢並聚焦**」，後端搜尋免申請公開地籍並回傳 centroid，**預覽底圖（Cesium）自動聚焦**至該地號並顯示待確認標記
5. 使用者可選「**確定此地號點位**」或「**重新選點**」，確定後寫入為正式選點，再進行下一步

### 最低必要欄位

支援以下格式（前端擇一輸入即可）：

```text
縣市：
鄉鎮市區：
地段：
小段：
地號：
```

例如：

```text
宜蘭縣
五結鄉
某某段
某某小段
123地號
```

若無小段，允許省略。

也接受單行詳細或模糊輸入：

```text
宜蘭縣五結鄉○○段123地號（詳細）
五結段123（模糊）
```

### 地號解析流程

Agent 必須：

1. 正規化縣市名稱
2. 正規化鄉鎮市區名稱
3. 正規化段名 / 小段名
4. 正規化母號 / 子號
5. 搜尋免申請之政府公開地籍圖資或公開查詢服務
6. 優先取得該地號 polygon
7. 若取得 polygon：
   - 以 polygon centroid 作為基地參考中心
   - 同時保留完整地籍 polygon 作基地界線候選
   - 於預覽底圖顯示待確認並可直接確定
8. 若只能取得地號位置而無 polygon：
   - 標記 `PARCEL_GEOMETRY_PARTIAL`
   - 使用可取得的位置作中心並於預覽底圖聚焦
   - 不得自行捏造地籍界線
9. 若公開資料無法解析：
   - 標記 `PARCEL_NOT_RESOLVED`
   - 請使用者補充地籍圖、坐標或改用地圖選點模式
   - 但繼續處理已可完成之資料準備工作

### 公開地籍前端要求

- 地號選點模式必須於前端提供公開地籍圖資嵌入（NLSC）供使用者對照，無需另開獨立視窗
- 預覽底圖（Cesium）需疊加 **NLSC WMS/WMTS 底圖**並同步聚焦至查詢結果，實現「輸入地號 → 底圖聚焦 → 確定點位」全前端閉環
- **確定點位後，前端自動回傳至 Agent 對話框**：同地圖選點，座標自動 POST 至 `/api/site/set` 並顯示完成頁，其餘轉由 Agent 作業

### 地籍限制

公開圖資僅供 GIS 初步定位與分析。

不得把本技能產生之地籍位置當作：

- 法定鑑界成果
- 土地登記證明
- 地籍複丈成果
- 建築線核定成果

## 6.3 圖說資訊可信度

所有由圖說自動擷取之數值必須標示：

- `EXPLICIT_TEXT`：圖說明確文字
- `DIMENSION_LABEL`：尺寸標註

不得把 `DERIVED` 或 `UNCERTAIN` 當作正式設計值。

# 7. 擬建工程 3D 模型建立

優先順序：

1. 使用者提供 GLB / glTF
2. 使用者提供 IFC / BIM，轉換為可用格式
3. PDF / 圖說解析出 footprint + height
4. 手動輸入長、寬、高
5. 只建立概念性 LoD1 量體

若高度未知：

不得虛構。

應顯示：

```text
MODEL_HEIGHT_UNKNOWN
```

並要求使用者補充或以圖說解析。

# 15. Google Maps 人工核對驗證 Gate

Google Maps 僅可作為「人工視覺核對參考」。

不得由 Google Maps 自動抽取 GIS 幾何或建立衍生地理資料。


## 15.1 核對項目

- 建物樓層或高度是否明顯異常

### B. 道路

- 道路位置
- 道路走向
- 道路交叉位置
- 主要道路是否缺漏

### C. 河川與水系

- 河川位置
- 河道走向

### D. 公共設施

- 醫院 / 診所
- 公園
- 政府機關
- 車站

- 基地中心點
- 地號定位結果
- 基地與鄰近道路關係
- 基地與周遭建物關係

---

## 15.2 核對方式

允許：

1. 使用者以 Google Maps 真實介面人工確認
2. 使用者提供 Google Maps 畫面截圖作人工比對參考
3. Agent 顯示政府 GIS 模型與基地定位結果，讓使用者並排比對
4. Agent 產生「待確認差異清單」
5. 使用者確認或修正差異

不得：

- 自動批次擷取 Google Maps 圖磚
- 從 Google Maps 自動描建物 footprint
- 從 Google Maps 自動建立道路 GIS
- 從 Google Maps 自動建立建物高度
- 將 Google Maps 視覺判讀值冒充官方資料

---

## 15.3 樓層與外型核對規則

Google Maps / Street View 等視覺內容只可用於「人工合理性核對」。

例如：

```text
官方/公開資料：建物高度 18m
人工目視：疑似約 5~6 層
結果：合理，PASS
```

或：

```text
模型：2 層
人工目視：明顯為高層建築
結果：MISMATCH
```

若無正式樓層或高度資料：

不得因目視估算即寫成正式樓層。

應標記：

```text
VISUAL_ESTIMATE_ONLY
```

並列入可信度 D。

# 28. Agent 執行流程（Phase 1 前端，其餘 Agent 自動）

> **新流程：Phase 1 至 Phase 1 僅需前端操作，操作完成後其餘全部由 Agent 自動製作 3D 互動模型。**
> 前端僅負責：模式擇一（地圖選點 / 地號選點）→ 地址聚焦或地號查詢 → 預覽底圖點擊或確認 → 確定點位。
> 確定後顯示「交由 Agent 製作」按鈕，後續 Phase 2–12 無需使用者逐項點擊，由 Agent 自動完成並回報進度。

收到任務後必須依序執行，不得跳級。前端完成 Phase 1 後，Agent 自動接管。

## Phase 1 — 基地解析（前端操作，唯一需使用者互動）

前端直接完成（擇一）：

- **地圖選點**：地址輸入→聚焦→預覽底圖左鍵點擊→確定點位 / 重新選點
- **地號選點**：公開地籍嵌入→詳細/模糊地號輸入→查詢聚焦→確定點位 / 重新選點

1. 解析基地（WGS84 → EPSG:3826）
2. 建立中心點
3. 取得可用地籍 polygon
4. 轉換 TWD97
5. 顯示「Phase 1 完成，交由 Agent 製作 3D 互動模型」按鈕

> 此按鈕按下後，視為使用者授權 Agent 自動執行 Phase 2–12，中間無需再手動逐項確認。

## Phase 2 — 擬建工程解析（Agent 自動，並主動請求使用者提供資料）

Agent 接管後**必須主動向使用者請求**：

> 「請上傳基本設計 PDF / 圖說 / BIM / Excel，或告知本機端存放位址（例：D:\...\*.pdf），以便擷取工程參數。」

使用者可擇一：

- 直接於前端上傳檔案（`POST /api/pdf/parse`），或
- 貼上本機端位址（`POST /api/pdf/parse_by_path`），Agent 嘗試讀取

1. 解析 PDF / 圖說 / BIM / Excel
2. 擷取工程基本參數
3. 記錄頁碼與來源
4. 處理衝突
5. 建立擬建工程初步模型

若使用者暫不提供，Agent 標記 `MODEL_HEIGHT_UNKNOWN` 並於 Excel 建議補充資料，仍可繼續後續建模與分析。

## Phase 3 — 政府公開資料取得（Agent 自動）

1. 搜尋免申請政府資料
2. 檢查授權
3. 記錄年份
4. 記錄 CRS
5. 下載 / 介接
6. 裁切範圍

## Phase 4 — 現況 GIS 基礎建模（Agent 自動）

建立：

- 地形
- 道路
- 河川
- 建物
- 樓層 / 高度
- 土地利用
- 公共設施
- 基地
- 擬建工程位置

此階段禁止執行影響分析。

## Phase 5 — Google Maps 人工核對（Agent 自動比對 + 視覺參考）

逐項核對：

- 建物
- 道路
- 樓層 / 高度合理性
- 建物外型
- 河川
- 公共設施
- 基地位置

產生差異表。Agent 以政府公開資料為主，Google Maps 僅視覺參考，差異自動修正或標記。

## Phase 6 — 差異修正與再驗證（Agent 自動）

只要有重大差異：

返回 Phase 3 / Phase 4 修正。

直到：

```text
BASE_MODEL_STATUS = VALIDATED
```

## Phase 7 — 現況 3D 渲染（Agent 自動）

建立已驗證之現況模型。

禁止自動開始六大分析。

## Phase 8 — 現況確認（Agent 自動，視同已驗證）

Agent 完成驗證後自動設定：

```text
CURRENT_RENDER_STATUS = APPROVED
```

（原需使用者確認，現由 Agent 自動完成並於最終頁提供預覽供覆核）

## Phase 9 — 分析模式（Agent 自動，預設水文+生態）

Agent 自動套用建議分析（水文防災、生態、環境等），或依使用者 Phase 1 前預選，等待確認後自動執行。

## Phase 10 — 執行選定分析（Agent 自動）

只分析選定之主題。

## Phase 11 — 最終互動式網頁（Agent 自動）

建立：

- 現況
- 擬建工程
- 分析結果
- 前後差異
- 圖層控制
- 分析控制
- 來源與可信度

## Phase 12 — Excel 匯出（Agent 自動）

輸出：

- 基礎模型驗證
- 使用者選定分析
- 分析結果
- 資料來源
- 分析限制

# 31. 正式性聲明

所有現況渲染、分析網頁與 Excel 報告均應保留：

> 本系統之 Google Maps 僅作人工位置與現況視覺核對參考，不作 GIS 幾何、地籍、建物高度或其他正式地理資料之自動抽取來源。基礎模型係依政府公開資料與使用者提供資料建立，完成核對驗證後再執行所選影響分析。所有分析結果主要供規劃、方案比較及風險初篩使用；地籍界址、環境影響評估、交通影響評估、水理分析、結構安全、地質判定、工程設計及其他法定事項，仍應以主管機關正式資料、現地調查及依法執業之專業人員判定為準。
