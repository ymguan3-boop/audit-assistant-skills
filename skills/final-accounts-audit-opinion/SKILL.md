# 總決算審核意見自動生成技能

從**調查報告**與**核復檔案**彙整出決算審核結果之「重要審核意見」文稿，產出 Word 檔案（.docx）。

## 觸發方式

使用者說「生成總決算審核意見」「幫我生成總決算審核意見」「重要審核意見」時載入本技能。

---

## 前置檢查

- 確認已安裝 `python-docx`：`python -c "import docx"`，若無則執行 `pip install python-docx`

---

## 工作流程

### Step 1：詢問參考資料來源（必做）

**先詢問，不得跳過。** 參考資料至少需包含：

> 請提供下列參考資料來源（**至少1份調查報告**及**至少1份核復檔案**）：
> 1. **調查報告**：專案調查報告（.doc/.docx）路徑，例如「1141219…調查報告-主任核定.docx」
> 2. **核復檔案**：第1次及/或第2次核復（.doc/.docx）路徑，可多份，例如「1150209…第1次核復.docx」「1150310…第2次核復.docx」
> 3. 若需套用特定層級標題（如「乙、決算審核結果／貳、縣政府主管／五、重要審核意見」），一併提供；未提供時使用下列預設。

核復檔案可透過檔名或內容辨識，內容特徵為表格含「審核通知事項及內容／聲復理由或辦理情形／審計機關覆核擬處理意見」三欄，且主旨含「(第N次)」。

若使用者提供目錄而非檔案，先以 glob 列出該目錄下所有 .doc/.docx，請使用者挑選或由您依檔名特徵（含「調查報告」及「核復」）自動選取。

> **若缺少報告或核復任一方，須暫停並再次要求補齊。**

### Step 2：擷取參考檔案內容

對每一份參考檔案執行：

```powershell
python "C:\Users\ymguan\.config\opencode\skills\final-accounts-audit-opinion\generate_opinion.py" extract --input "<報告路徑>" --output "<暫存\report.txt>"
python "C:\Users\ymguan\.config\opencode\skills\final-accounts-audit-opinion\generate_opinion.py" extract --input "<核復(1)路徑>" --output "<暫存\reply1.txt>"
python "C:\Users\ymguan\.config\opencode\skills\final-accounts-audit-opinion\generate_opinion.py" extract --input "<核復(2)路徑>" --output "<暫存\reply2.txt>"
```

暫存目錄建議 `C:\Users\ymguan\AppData\Local\Temp\opencode\`。若僅一份核復，只跑一次即可。

若為 .doc 舊格式，先以 Word 另存 .docx 或使用 pywin32 轉檔後再擷取。

### Step 3：分析文稿架構

文稿固定為**5個段落**，來源映射如下：

| 輸出段落 | 格式 | 主要來源 |
|----------|------|----------|
| **P0 第一層標題** | 18pt 粗體 置中 | 章節層級（預設「乙、決算審核結果」） |
| **P1 第二層標題** | 18pt 粗體 | 主管單位層級（預設「貳、縣政府主管」） |
| **P2 第三層標題** | 16pt 粗體 | 條目層級（預設「五、重要審核意見」） |
| **P3 洞察段** | 14pt 粗體 | 報告查核發現之精簡摘要，句末標註（洞察） |
| **P4 主文段** | 12pt 一般 | 調查報告查核意見 + 核復內容（四段式彙整） |

**P4 主文段固定為「四段式」結構：**

```
① 法規背景與現況 → ② 查核發現（核有：…）→ ③ 審計機關處理作為 → ④ 核復結果（據復：…）
```

#### ① 法規背景與現況（取自調查報告「查核意見」開頭總論段）

格式：
> <受查機關>為提高<政策目的>，確保<政策目標>，促進<政策目標>，增進<公共福祉>，依<法規公布日期>公布施行之<法規名稱>辦理<許可、登記、撤銷或廢止、獎懲、複查及抽查>等作業。截至<基準日>止，<轄區>登記之<受查對象>計有<數量>家（含<舊制註記>），

#### ② 查核發現（取自調查報告「查核意見」各項之事實段，即「本室經運用…」段落）

格式：
> 經查其辦理<業務>執行情形，核有：**1.<發現標題>：<事實詳情>**，<為避免…建請…改善建議>；**2.<發現標題>：<事實詳情>**。另查<補充發現>。

- 依查核意見項目整理歸併為「1、2、…」大項；同主題項目（如複查、罰鍰）可併為一項。
- 每項內容含：家數／件數／金額／機關別／基準日等量化事實。
- 政府電子採購網自動檢核等改善建議，以「為避免…，建請…」句式帶入。

#### ③ 審計機關處理作為（取自調查報告「捌、擬議處理意見」及查核意見結尾「擬通知…」）

格式：
> 經函請<受查機關>本<主管機關權責>權責，責請<採購機關>查明釐清<事項>，與加強辦理<複查、罰鍰催繳及移送強制執行>等，依法妥處。

#### ④ 核復結果（取自核復檔案「聲復理由或辦理情形」及「審計機關覆核擬處理意見」，改寫為第三人稱客觀敘述）

格式：
> 據復：**1.<核復第1項結果>**；**2.<核復第2項結果>**。

- **以最新一份核復之最終結論為準**（第2次核復優於第1次核復）。
- 機關聲復理由與審計覆核意見合併改寫為「已……、另……、並……、將……」之完成式敘述。

### Step 4：P3 洞察段撰寫規則

格式：
> （   ）  為提高<政策目的>，確保<政策目標>，持續辦理<業務作業>，惟<發現1摘要>，且有<發現2摘要>，亟待檢討改善。（洞察）

- 開頭「（   ）」為條目編號留白（3個半形空格），句末固定標註「（洞察）」。
- 全文 14pt 粗體，內容為查核發現之**一句話精簡摘要**，不得出現數字細節。
- 以「惟…，且有…」帶出問題點，結尾固定「亟待檢討改善」。

### Step 5：資料校對規則

撰寫主文前必須校對以下項目，確保數字一致：

| 校對項目 | 原則 |
|----------|------|
| 家數／件數／金額 | 以**最新核復**數字為準，不得沿用報告舊值（例如罰鍰未繳家數報告為3家、核復後改為2家） |
| 基準日 | 以查核日／核復函文日期為準，保留「截至…止」句式 |
| 廠商名稱 | 一律匿名化（如「永○營造有限公司」），不得出現完整商號 |
| 表格引用 | 以「（表○）」佔位，不寫實際表號 |
| 機關全稱 | 首次出現用全稱，其後可用簡稱並以「（下稱…）」註明 |
| 金額單位 | 若出現金額，一律加註「新臺幣」，單位為元/萬元並說明 |

### Step 6：撰寫 content.json 並產出 WORD

依下列結構撰寫暫存檔 `C:\Users\ymguan\AppData\Local\Temp\opencode\opinion_content.json`：

```json
{
  "l1": "乙、決算審核結果",
  "l2": "貳、縣政府主管",
  "l3": "五、重要審核意見",
  "insight": "（   ）  為提高營造業技術水準，確保營繕工程施工品質，持續辦理營造業之許可、登記等作業，惟部分機關於投標廠商辦理停業後之審標程序未盡妥適，且有部分廠商未依營造業法規定期限申請複查及逾期未繳交罰鍰情事，亟待檢討改善。（洞察）",
  "main": "縣政府為提高……據復：……"
}
```

> 內容含中文字與換行，請以 write 工具寫檔（UTF-8），勿使用命令列 here-string 避免編碼問題。

執行：

```powershell
python "C:\Users\ymguan\.config\opencode\skills\final-accounts-audit-opinion\generate_opinion.py" build --content "C:\Users\ymguan\AppData\Local\Temp\opencode\opinion_content.json" --output "<輸出 docx 路徑>"
```

預設輸出檔名：`總決算審核意見_重要審核意見.docx`。

### Step 7：產出檢核

產出後逐項檢核：

| 檢核項目 | 檢查點 |
|----------|--------|
| 段落數 | 應為5段（P0～P4） |
| 標題層級 | P0置中18pt粗體／P1、P2縮排粗體 |
| 洞察段 | 以「（   ）」開頭、「（洞察）」結尾、14pt粗體、無數字細節 |
| 主文四段式 | ①法規背景②查核發現③審計處理④核復結果，四段齊備且順序正確 |
| 核復來源 | 以最新核復結論為準，數字與報告一致 |
| 匿名化 | 廠商名稱均有「○」遮罩 |
| 標點符號 | 全形標點、「據復：」「核有：」「經函請」等慣用語正確 |

若檢核發現問題，修正 content.json 後重新執行 Step 6。

## 注意事項

1. 參考資料至少需**1份調查報告**與**1份核復檔案**，缺少任一方即暫停並要求補齊
2. 僅支援 .docx 讀取；.doc 需先轉檔
3. content.json 請以 write 工具寫入，確保 UTF-8 編碼
4. 產出後可開啟 Word 核對格式
