# 採購申訴審議判斷書簽文撰寫技能

從採購申訴審議判斷書PDF自動OCR擷取內容，產出審計機關簽辦公文（MD格式，可直接複製貼入公文系統）。

## 觸發方式

使用者說「幫我寫判斷書簽」「申訴審議判斷書簽文」「judgment-draft」「判斷書簽」時載入本技能。

## 工作流程

### Step 1：收集判斷書檔案

向使用者詢問：

> 請提供採購申訴審議判斷書PDF檔案路徑。
> - 若檔案在網路芳鄰（\\\\192.168.209.100\\...），請提供完整路徑
> - 若需從PCC網站下載，請先手動登入後提供案號

若使用者未提供，可至以下位置搜尋：
- `\\192.168.209.100\11__第三課\29.審議判斷書\` 目錄下搜尋

### Step 2：OCR讀取PDF內容

```python
python -c "
import sys, io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
from pdf2image import convert_from_path
import pytesseract
pytesseract.pytesseract.tesseract_cmd = r'C:\Program Files\Tesseract-OCR\tesseract.exe'
images = convert_from_path(r'<PDF路徑>', dpi=300)
text = ''
for i, img in enumerate(images):
    text += f'=== 第{i+1}頁 ===\n'
    text += pytesseract.image_to_string(img, lang='chi_tra+eng')
    text += '\n'
with open(r'C:\Users\ymguan\AppData\Local\Temp\opencode\judgment_ocr.txt', 'w', encoding='utf-8') as f:
    f.write(text)
print(f'Total pages: {len(images)}, chars: {len(text)}')
"
```

若同目錄下有 `.di` 檔案（XML描述檔），一併讀取以取得來文字號、主旨等公文資訊。

### Step 3：分析判斷書內容

從OCR文字中擷取以下關鍵資訊：

| 欄位 | 說明 |
|------|------|
| 判斷書字號 | 如「訴1150115號」 |
| 來文機關 | 如「審計部第五廳」 |
| 來文字號 | 如「審五字第1155001558號」 |
| 來文日期 | 如「115年7月29日」 |
| 工程會函字號 | 如「工程訴字第1151101263號」 |
| 申訴廠商 | 廠商名稱及代表人 |
| 招標機關 | 機關名稱及代表人 |
| 系爭採購案名 | 採購案完整名稱 |
| 爭議類型 | 如「投標資格限制」「押標金追繳」等 |
| 判斷結果 | 「申訴駁回」或「申訴有理由」 |
| 申訴方主張 | 申訴廠商之主要論點 |
| 招標機關主張 | 招標機關之答辯理由 |
| 工程會經查事實 | 工程會認定之事實及法律適用 |
| 是否涉及罰則 | 是否有停權、追繳押標金等事項 |

### Step 4：產出簽辦公文

按以下格式撰寫MD檔案：

```
簽

檔　　號：<民國年>/030501/
保存年限：10年

主旨：<機關>檢送<案件名稱>採購申訴審議判斷書（<字號>）一案，謹研析處理意見，簽請鑒核。

說明：

一、依<來文機關>中華民國<日期>字號函（依行政院公共工程委員會<日期>字號函副本）辦理。

二、旨案緣係<完整案件背景描述，說明申訴廠商、招標機關、採購案名、爭議緣由、申訴經過>，遂向工程會申訴。

三、經據工程會檢送旨案採購申訴審議判斷書略以：
（一）申訴廠商主張<申訴方主要論點，逐點摘錄>。
（二）招標機關主張<招標機關答辯理由，逐點摘錄>。
（三）經查<工程會經查事實認定及法律適用，作為本段小結>。<判斷結果>等情。

四、<依判斷結果，從審計觀點作客觀結論，見下方「說明四撰寫原則」>。

擬辦：

一、<依說明四所簽內容，分條列述擬辦事項>。

二、另本案採購申訴審議判斷書所述之判斷理由，擬併作為稽察業務參考。

以上所擬，是否有當？敬請核示。

正本：<受文機關>
副本：

　　　　　　　　　　　　　　　　　承辦審計　○○○　謹簽

附件：
一、行政院公共工程委員會函（字號）影本1份。
二、採購申訴審議判斷書（字號）影本1份。
三、<來文機關>函（字號）影本1份。
```

### Step 5：儲存檔案

將簽辦公文儲存至使用者指定路徑，或預設路徑：
- `D:\opencode_0519\2ndbrain\資料庫建置及產出\分析報告\簽辦-<案號>-<採購案名>.md`

若同目錄下有 `1.來函及簽\1.簽.docx` 或其他參考簽檔，讀取其Description欄位作為格式參考。

### Step 6：撰寫後檢核

簽辦公文產出後，**必須逐段檢核**以下項目：

| 檢核項目 | 說明 |
|----------|------|
| 說明二文法通順 | 「旨案緣係……」語句是否流暢，無語病 |
| 說明三邏輯正確 | 申訴方主張→招標機關主張→經查事實，三層次是否清晰 |
| 說明三完整性 | 是否涵蓋雙方主要論點，無遺漏重要爭議 |
| 說明四與說明三銜接 | 小結事實是否足以支持說明四之結論 |
| 說明四客觀性 | 是否以審計觀點作出客觀結論，非僅複述判斷理由 |
| 擬辦與說明四一致 | 擬辦事項是否與說明四內容對應 |
| 結語完整 | 是否包含「以上所擬，是否有當？敬請核示」 |
| 用語一致 | 機關名稱、案號、字號全文是否一致 |

若檢核發現問題，自動修正後重新輸出。

## 說明三撰寫結構（三層次）

說明三須依以下順序撰寫，層次分明：

### 第一層：申訴方主張
摘錄申訴廠商之主要論點，以「（一）申訴廠商主張……」開頭。逐點列出，保留原判斷書用語。

### 第二層：招標機關主張
摘錄招標機關之答辯理由，以「（二）招標機關主張……」開頭。與申訴方主張對應。

### 第三層：工程會經查事實（小結）
以「（三）經查……」開頭，摘錄工程會認定之事實、法律適用及判斷理由。本段為說明三之小結，須明確交代判斷依據。

## 說明四撰寫原則（依判斷結果分類）

### 類型一：招標機關尚無不法（申訴駁回）

當判斷結果為申訴駁回，且招標機關適用法規尚無違誤時：

```
四、本案經工程會審議判斷申訴駁回，認定招標機關依政府採購法施行細則
    第○條第○項第○款規定通知申訴廠商投標資格不符，於法有據。經核尚
    無未妥，擬予存查，並賡續注意本案後續辦理情形。
```

> **注意**：此類型不需強引法規作為函請機關檢討改進之依據，僅需以審計觀點作出客觀結論。

### 類型二：招標機關有需改進之處

當判斷結果雖為申訴駁回，但審計監督發現招標文件或作業程序有需改善時：

```
四、本案經工程會審議判斷申訴駁回，認定招標機關適用法規於法有據。惟
    查招標機關辦理類此延續性採購案時，招標文件對○○之規範未臻明確，
    易生爭議。擬函請宜蘭縣政府就旨揭採購案相關招標文件及資格審查作
    業程序檢討改善，並將辦理情形復知本室。
```

### 類型三：招標機關有違法或不當（申訴有理由）

當判斷結果為申訴有理由，認定招標機關有違法或不當時：

```
四、本案經工程會審議判斷申訴有理由，認定招標機關○○○○之處分違反
    政府採購法第○條規定。擬函請宜蘭縣政府依政府採購法第○條第○項
    規定處置，並將辦理情形復知本室。
```

### 類型四：不受理

```
四、本案因申訴廠商未繳審議費或補正申訴書，經工程會依政府採購法第○
    條規定不予受理，有關申訴案件情由，擬列入稽察選案參考，來文擬存
    查。
```

## 判斷結果與處理對應

| 判斷結果 | 說明四方向 | 擬辦方向 |
|----------|-----------|----------|
| 申訴駁回（尚無不法） | 經核尚無未妥，擬予存查 | 存查，賡續注意後續辦理情形 |
| 申訴駁回（有需改進處） | 擬函請機關檢討改善 | 函請機關改善，復知本室 |
| 申訴有理由 | 擬函請機關依法處置 | 函請機關撤銷/變更原處分 |
| 不受理 | 列入稽察選案參考，來文存查 | 存查 |
| 涉及押標金追繳 | 函請機關依第31條規定辦理 | 函請機關追繳，復知本室 |
| 涉及停權處分 | 函請機關依第101條規定辦理 | 函請機關依規定處置，復知本室 |

## 格式要點

| 段落 | 格式要求 |
|------|----------|
| 說明一 | 依<來文機關>字號函辦理 |
| 說明二 | 「旨案緣係……遂向工程會申訴。」 |
| 說明三 | 「經據工程會檢送旨案採購申訴審議判斷書略以：（一）申訴廠商主張……（二）招標機關主張……（三）經查……等情。」 |
| 說明四 | 依判斷結果分類撰寫（見上方「說明四撰寫原則」） |
| 擬辦 | 分條列述，引用說明四內容 |
| 結語 | 「以上所擬，是否有當？敬請核示」 |

## 注意事項

1. OCR需安裝 Tesseract（`C:\Program Files\Tesseract-OCR\tesseract.exe`）及 pdf2image、pytesseract
2. OCR品質受掃描品質影響，文字可能有誤差，需人工校對
3. 若PDF為文字版（非掃描），可嘗試直接讀取而免OCR
4. `.di` 檔案為XML格式，可精確取得來文字號、主旨等資訊
5. 簽辦公文為MD格式，使用者可直接複製貼入公文系統
6. 產出後提醒使用者檢查文字是否因OCR誤差需修正
7. **說明四不一定需要引用法規**，應依判斷結果及審計觀點決定撰寫方向
8. **撰寫後必須執行Step 6檢核**，確保各段文法及邏輯通順
